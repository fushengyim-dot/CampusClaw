# Design: 教师签发邀请码的账号注册

## Decisions

1. 首位教师仍使用现有预置教师账号登录。教师登录后只可给自己的班级签发角色固定的邀请码；学生码和教师码分开签发，注册页不接受角色或班级字段。
2. 邀请码由密码学安全随机源产生，数据库只保存带唯一摘要的记录。明文只返回给签发教师一次，不进入日志或后续列表。记录包括班级、签发者、目标角色、过期时间、撤销时间和消费时间。
3. 注册以单个数据库事务消费邀请码并创建用户。消费时锁定邀请码行，检查状态，再插入用户并标记已使用；唯一用户名约束处理并发重名。失败回滚，不会留下半消费状态。
4. 用户名沿用现有UTF-8长度限制并去除首尾空白；新密码至少12个Unicode字符且最多72个UTF-8字节，以bcrypt存储。注册成功后创建与现有登录相同的服务端会话和HttpOnly Cookie。
5. 不区分“邀请码不存在/过期/已用/撤销”的公开错误文案；不回显邀请码。用户名冲突使用通用注册失败文案，避免通过错误响应探测账号。
6. 教师签发、撤销接口必须检查登录态、教师角色、同班边界和Origin。教师不能操作其他班级的邀请码；学生不能签发或撤销。
7. 迁移只新增邀请码表，不重写用户或种子数据；重复启动遵循既有版本迁移策略。

## Risks and mitigations

- 邀请码泄露会允许他人创建该码绑定班级/角色的账号；限制为一次使用、短期有效、仅创建时展示并提供撤销。
- 并发重复提交可能造成重复消费；使用事务行锁与唯一约束，并做数据库并发集成检查。
- 不能证明新注册者现实身份；该作业阶段采用教师分发邀请码作为准入边界，不宣称实名验证。
