# 第4课技术方案

## Context

第3课已归档并有真实MySQL/HTTP/浏览器/容器证据。本地代码目前只有`knowledge_entries`保存整份原文，没有切片、全文索引、向量库或问答接口。技术实现依赖页面见`docs/lesson-04/internal/COURSE_REVIEW.md`；原始`knowledge-retrieval` spec目前无法从公开路由取得，以下以已检索到的教师教程为依据，并保留该限制。

## Decisions

### D10：MySQL保留原文和可引用切片

不改写第3课`knowledge_entries.content`。每个切片独立保存班级、材料、原文条目、序号、文本和字符位置；材料标题、出处和切片正文由MySQL取回。采用新迁移，不改写已应用的001迁移；版本检查须保持现有不覆盖和重放安全规则。

### D11：三种切分策略

- `auto`：最多约800字符，重叠80字符，优先在段落、换行和句号断开。
- `custom`：自定义分隔符，长度100—2000字符，重叠0—50%。
- `hierarchy`：按Markdown标题层级分章，保留标题；过长章节再用自动窗口。

可选预处理仅改变切片输入；原文件和`knowledge_entries.content`保持不变。字符偏移按实际切分输入计算并随响应明确标注，不冒称为原始文件位置。

### D12：关键词、向量及融合

`keyword`只查MySQL `FULLTEXT ... WITH PARSER ngram`，token长度2；不调用嵌入或Qdrant。`vector`用问句向量查Qdrant，并用会话班级过滤；余弦低于0.35的候选丢弃，按向量主键回MySQL并再次校验班级。`hybrid`先按各自规则筛选，再用`RRF(k=60)`融合名次，不直接相加异构分数。

`knowledge_chunks.index_status=ready`仅表示文本切片及MySQL关键词索引可用；向量是否已写入Qdrant单独判断。原始教师规格未取得，关于“嵌入失败”的状态语义保留待核对。

Qdrant仅保存向量和标识payload，不存正文；向量主键与切片ID一致，payload只放班级、材料、条目、切片等ID与序号。Qdrant不可用时，关键词模式仍可用；vector/hybrid返回503，不伪造分数。

### D13：证据门控的简短问答

`/api/ask`只在服务端取得会话身份后，以最新问题运行本班hybrid检索，最多取4条切片。无命中时返回固定无结果文案及空citations，不调用对话服务。命中后才调用服务端网关，将切片标题、序号、正文和最新问题交给生成端；允许附加此前若干轮对话供连续追问，但历史对话不参与检索。回答编号与citations顺序一致。客户端system消息、向量分量和其他班数据不传入模型。流式输出留到第5课。

### D14：外部服务和费用边界

Qdrant使用本地容器；代码和模拟接口可在本地验收。课程网关真实调用必须有用户明确授权。已授权并完成一条自拟短句的嵌入连通测试，但这不授权批量发送讲义或对话内容。费用、配额和数据保留政策仍未知；讲义嵌入须由教师在界面显式启动，问答请求只在用户主动提交问题且检索有证据时发送。

### D15：向量索引由教师明确启动并可复用

上传后默认只在本地生成MySQL切片，不把讲义自动发送到外部网关。教师在材料详情中明确启动向量索引后，后端按当前会话班级读取切片并逐片调用嵌入服务，写入Qdrant；客户端不接触密钥。另用独立表记录每个切片的向量状态和正文SHA-256。只有状态为ready且哈希与当前正文一致的切片可参与语义检索；失败项可由教师重新启动，未变化项跳过。接口每次最多处理10个待索引切片，不自动重试，避免一次点击意外消耗过多额度。

## Risks / Trade-offs

- 原始规约尚不可得，公开教程可能未覆盖某些教师验收边界；不得将教程覆盖等同于canonical spec已核对。
- MySQL的中文ngram全文索引须在当前MySQL 8.4镜像上实际验证。
- 数据库与Qdrant不是同一事务；需要以可重复的索引状态和失败处理避免把缺向量误报为可检索。
- 输入预处理会使切片字符区间相对转换后的文本，而非原文件；页面须准确说明。
- 外部模型请求未授权/费用未知；本地mock测试不能称为真实网关验收。

## Acceptance approach

先验收纯切片算法和MySQL关键词路径，再验收Qdrant本地向量/混合流程和班级隔离。课程网关只在用户主动授权对应内容外发后调用；目前有一条自拟短句嵌入请求成功的记录，不代表讲义或问答获准外发。模拟接口检查不能称为真实网关验收。
