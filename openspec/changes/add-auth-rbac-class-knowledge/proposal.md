# 第一轮：登录、角色权限、班级隔离与讲义上传

## Why

本门软件开发课程的讲义分布在教师网页、课件和实操教程中。教师需要把整理后的课程资料放到本班平台，学生需要登录后查看本班资料。后续的讲义问答、解题引导和复习整理，必须以可信的身份、明确的班级范围和已保存的正文为基础。

本轮先把“谁在使用、能看哪一班、谁能上传、上传后是否真正保存”做成可检查的基础能力。

## What Changes

- 教师与学生用预置账号和密码登录；建立服务端会话，支持退出。未登录访问受保护页面进入登录页；受保护 API 返回 401 且无业务数据。
- 教师可上传、查看、下载本班讲义；学生可查看、下载本班讲义，上传请求返回 403。检查必须由 Go 服务端执行。
- 列表、详情、下载和正文查询按会话解析出的班级过滤。跨班 ID 与不存在的 ID 返回同构 404，不泄露对方资料。
- 教师上传 UTF-8 `.txt` 或 `.md` 后，原文件、材料记录和知识库正文关联保存；本班成员刷新可见。失败时回滚数据库并清理新增文件。
- 准备 A/B 两班、各班教师和学生，以及标题可区分的样例资料；同时保留第 2 课要求的六类核心实体结构，未到课次的业务仅占位。
- 密码哈希存储，配置从服务端环境变量读取。未来由 Docker Compose 启动，提供免登录 `/health`，数据库和上传文件使用持久化数据卷。
- 第 3 课补齐 README 的真实启动方式、配置样例和运行验收记录；本次仅交付规约。

## Capabilities

### New Capabilities

- `auth-upload`：登录与会话、教师/学生权限、班级隔离、材料上传与正文入库、可复现样例、密码及配置保护、Compose 启动与数据保留。

### Modified Capabilities

无。本仓库尚无已实现并归档的能力。

## Non-goals

- 本轮不做切片、向量嵌入、检索、AI 回答、聊天页面、提示词模板、技能执行或 MCP。这些仍是后续课程目标，并未取消。
- 不做注册、找回密码、验证码、单点登录、超级管理员、一个账号加入多个班级或班级切换。
- 不做讲义在线编辑、覆盖、删除或版本管理；本轮“管理材料”限定为上传、查看和下载。
- 不在服务器中解析 PDF、PPT、Word、图片或压缩包，不接受 URL 自动抓取。课程网页与课件先由助手在资料准备环节转换并核对为文本，再由教师上传。
- 不做作业发布/提交/批改、成绩、错题库、异步任务或消息队列；作业实体只为第 2 课结构要求保留最小占位。
- 不调用外部模型，不连接真实第三方工具，不公开部署，不做高可用、Kubernetes 或完整发布流水线。
- 不读取、导入或修改旧 `F:\CampusClaw` 的代码、账号、数据库或配置。

## Impact

第 3 课将新增 `frontend/`、`backend/`、`deploy/nginx/`、`compose.yaml`、`.env.example` 与必要 Dockerfile。数据库为 MySQL；正文保存于 `knowledge_entries`，尚不产生向量索引。运行数据留在 Docker 命名卷，不纳入 Git。

当前先新增本变更四件套和必要项目说明，全部实现工作按 `tasks.md` 在用户确认后推进。
