# 设计：MCP 工具接入

## 1. 背景与教学顺序

沿用第5课 Go、MySQL、React/TypeScript、Nginx 与 Compose。依次实现：自建 MCP 服务 → 服务器登记和发现 → 技能绑定 → 模型工具调用宿主编排 → 教师管理和记录 → 本地模拟验收。每一步都能单独检查，不以工具模型在线能力代替本地 stub。

## 2. MCP 协议轮廓

- 课程明确要求 `initialize`、`tools/list`、`tools/call` 和 HTTP 传输，因此本地服务实现 JSON-RPC 2.0、单一 `/mcp` POST 端点和 `Authorization: Bearer`；当前选用握手型协议版本 `2025-11-25`，并使用无状态 HTTP 会话，不生成会话令牌。
- 初始化协商协议版本与 `tools` 能力；发现响应的工具名称、完整说明和输入 JSON Schema 是模型声明的唯一来源；调用结果使用 `content: [{type:"text",text:...}]` 与 `isError`。
- MCP 官方规范在 2026-07-28 发布新一代无握手协议，和老师本课明确的初始化握手要求不同；本项目按课程验收使用最新握手型版本，而不宣称实现新一代生命周期。参考：[MCP 2025-11-25 规范变更记录](https://modelcontextprotocol.io/specification/draft/changelog) 与老师[第6课协议页面](https://devops.hello1023.com/课件/第6课-课件-MCP与工具接入/pages/mcp-model.html)。
- 服务仅实现课程要用的三个 JSON-RPC 方法；未知方法、版本不匹配、无效参数和认证失败返回可读 JSON-RPC 错误，不包含凭证。

## 3. 工具选择

自建 `campus-tools` 服务只提供两项无副作用工具：

1. `lookup_course_term(term)`：在版本化的本地软件开发课程词条数据中查找精确或包含匹配，最多返回三条。
2. `next_step_hint(topic, observed_result)`：按预设课程主题返回通用排查/下一步清单；`observed_result` 做长度限制和秘密样式脱敏后才参与匹配，绝不运行代码或连接用户提供的地址。

工具说明明确提示“只给下一步，不替学生完成作业”；输入字段有 JSON Schema 上限，返回短文本。管理页展示完整工具说明，供教师判断工具是否适用。

## 4. 登记、凭证和连接状态

- `mcp_servers` 按班存名称、URL、令牌密文、是否已配置、是否连接、最近错误和发现时间；同一班服务器名唯一。认证、角色、班级范围都由后端会话决定。
- 令牌使用 AES-GCM 加密后写入 MySQL；密钥由现有随机会话秘密通过独立用途标签派生。API 从不返回令牌原文，列表只返回 `token_configured`。表单使用密码控件，保存后立即清空。日志、错误和镜像不包含令牌。
- 出站 HTTP 客户端禁用重定向，限制请求体、响应体和超时。只允许 HTTPS 公网地址或本地预置 MCP 服务地址；拒绝 file、ftp、localhost、链路本地、云元数据和任意 loopback URL，避免把接口变成 SSRF 代理。
- 连接流程为：读取本班登记 → 带 Bearer 发送 initialize → 协议版本校验 → tools/list → 验证清单结构/数量/大小 → 单个事务替换整份工具快照并设连接。任一步失败时清空可用清单、设未连接并保存脱敏错误。
- 断开使用事务清空发现工具并将状态设未连接。已有技能引用保留用于教师查看，但任何对话执行都因清单不存在而拒绝；重新发现后如工具说明/schema 哈希变化，旧绑定需教师重新保存确认。

## 5. 数据与绑定

- 迁移006新增 `mcp_servers`、`mcp_server_tools`、`course_skill_tool_bindings`、`mcp_tool_calls`，不回写001—005。
- 工具引用格式严格为 `tool_name@server_name`。技能保存时必须在同班已连接服务器的最新清单中找到该工具；只记录经教师保存确认的工具哈希。
- 本次工具候选只取已选中技能绑定的工具，并额外受代码侧白名单、服务器连接状态和最近发现快照约束。未被技能引用的工具不会传给模型。
- 审计调用含服务器名快照、工具名、状态、用户、班级、会话、轮次、发生时间、结果摘要或安全错误码；不保存参数、令牌、原始返回或聊天上下文。服务器删除后历史记录仍可读。

## 6. 宿主调用循环

- 增加 OpenAI-compatible 流式工具调用客户端，累计 delta 中分片到达的工具名/调用ID/JSON 参数，再在宿主端完整解析。
- 模型只提议调用。宿主验证调用ID、候选工具名、单个 JSON 对象、当前 schema、字符串字段上限、同班技能绑定、服务器连接和工具快照哈希后，才调用远端 MCP。
- 硬上限：每次提问最多3轮、最多4次工具调用、每个工具调用10秒、整个工具阶段30秒。达到任一上限后停止后续调用，保留已有信息并让模型生成说明性回答。
- MCP 失败、工具 `isError`、超时、拒绝和安全检查命中都会回传简短工具错误消息并继续主对话；失败不会让整条检索问答中断。
- 工具说明和工具返回均为不可信数据。工具输出拒绝包含明显指令式注入句式；系统消息继续声明工具输出只在工具数据位、不具备更改规则权限。此启发式只降低风险，不提供绝对安全保证。
- 对话先发送 SSE `meta`（工具清单可为空），再在实际执行前推送 `tool/running`；每次可归属调用结束后先持久化审计，再立即推送结果状态，最后才发送正文 `delta`。实际工具输出不直接作为 SSE 响应返回。工具决策最多3轮，随后单独发起一次禁止继续调用工具的正文流式请求，总模型请求最多4次；普通无工具候选问答仍只有1次请求。详见 `fix-mcp-answer-streaming`。

## 7. 验证范围

- `httptest` 假服务器验证握手、发现、替换、认证、调用、错误状态和 HTTP 限制；测试服务器与本地假模型均不访问公网。
- 服务测试验证 schema 参数复核、未连接/未知/跨班拒绝、句式检查、上限、审计脱敏和工具消息回传。
- UI 只提交合成服务器与 token；使用短期本地工具服务，测试结束清理自己建立的记录。禁止使用真实令牌或真实课程内容。
- 同伴的服务器隔离、令牌不回传、断开失效、个人记录查看必须留待第二个真实账号操作者；本机测试只能记为模拟通过。
