# 第6课：接入 MCP 工具服务器

## Why

第5课已经提供本班智能体、技能、私有会话与流式回答。本课要在其上接入一个独立的 HTTP MCP 工具服务，让宿主负责发现、权限校验、执行、结果检查和记录；模型只提出结构化调用，不接触服务器地址或令牌。

## What Changes

- 新增一个带 Bearer 认证的 MCP Streamable HTTP 服务，提供两个只读软件开发课程工具。
- 教师可登记服务器、提交或更新令牌、连接并发现工具、断开并清空最近清单；返回值不含令牌原文。
- 增加技能与发现工具绑定；绑定只允许 `tool_name@server_name` 且须指向已连接服务器的当前清单。
- 在流式会话中按发现清单生成模型工具声明，验证模型给出的参数，受限地执行工具、检查结果并把工具消息交回模型。
- 增加每次工具调用的服务端审计记录、教师管理页和个人调用记录页；SSE 的 `meta` 在回答 `delta` 前带出本轮工具结果摘要。

## Non-goals

- 不发送任何真实课程模型请求，不把讲义或真实个人数据发往第三方服务。
- 不执行命令、写文件、发消息、修改课程数据或提供其他有副作用的工具。
- 不实现资源和提示词两类 MCP 能力、指标/追踪系统、第8课安全流程、公开部署或公网发布。
- 不把第5课同伴验证或第4课真实材料验收状态改写为通过。

## Acceptance

- MCP `initialize`、`tools/list`、`tools/call`、正确/错误 Bearer、工具参数与返回均由本机合成测试覆盖。
- 重复发现替换旧清单；断开立即清空清单并拒绝相关调用；工具引用保存前按当前清单校验。
- 离线模型 stub 覆盖结构化工具调用、回传、多轮与上限、失败优雅降级、SSE 事件顺序和审计脱敏。
- Go/前端构建、Compose 配置、迁移重入、本机容器与 UI 页面检查通过；外部模型与同伴验证分开记为待验。
