# 设计

工具决策与正文生成分开：保留最多3轮结构化决策，沿用已绑定工具、参数检查、审计与4次工具执行上限。决策轮出现无工具请求的响应时，其完整文字只作为结束决策的信号，不先展示或再拆分；从原问题及已完成工具消息生成一次真正的流式正文。达到决策轮上限后直接进入禁止工具的正文阶段，不再增加非流式收尾轮。

生产ChatClient实现StreamToolAnswer，可序列化assistant.tool_calls和tool.tool_call_id，发送stream:true、tool_choice:none。不再包含可调用工具定义。工具阶段最多30秒，正文使用原请求上下文和既有流式超时。断流保留已接收内容并返回错误，不重试。旧本地fake模型可以保持非流式接口兼容，生产处理器使用具备流式能力的ChatClient。

处理器在实际执行工具前发meta（tools初始为空），每次running/success/error/rejected/timeout事件立即写出并flush。工具阶段不会发送正文；正文回调到达即发送delta，结束后保存数据库并发done。前端将工具事件作为当前会话本轮的状态列表，在回答区域前显示中文结果；切换会话、新建会话、新问题清空，自动回读本轮消息时保留。

验证以本地HTTP服务器和分段闸门确认首段在末段放行前已经到达；另测工具上下文序列化、请求上限、无工具候选普通流不变、中断落库、错误脱敏与前端渲染。

续验发现一次POST新建会话返回503，但随后读到空会话64。根因尚未确认，不能断言数据库未写入。前端使用独立creating状态锁住重复点击，失败后只读刷新列表并保留错误，不自动重试写入。这是失败恢复措施，不把服务器异常判为已解决。
