# 第5课技术方案

## Context

项目使用Go、MySQL、React/TypeScript、Nginx与Docker Compose。现有`001_initial.sql`只有薄的`tutor_agents`/`skills`表；已有第4课检索服务与非流式`ChatCompleter`。迁移只追加版本，不改写001—003，不清除数据。第5课要求不同于第4课的无证据固定拒答：本课检索落空仍生成角色回答，但不得有虚构引用。

## Decisions

### D1：数据与迁移
追加迁移004建立会话、消息、技能字段与绑定；迁移005建立每班三个内置应用键到智能体的稳定映射。智能体和技能保留class_id；名称班内唯一；会话同时保存class_id、user_id、agent_id。外键/唯一键阻止跨班绑定。迁移保持项目现有schema checksum及重入策略；不得重置数据。

### D2：权限与资源语义
每个handler从现有Cookie会话取得用户身份、班级和角色。教师写接口跨班/不存在对象统一404，学生调用教师写接口403。学生只能列出本班启用智能体；按ID访问他班/停用智能体与不存在完全同样404。会话读写按本人+班级双过滤，跨用户/跨班/不存在统一404。会话的agent_id创建后不可被请求体更改；已停用智能体的旧会话仍可继续。

### D3：技能文件与预置
解析课件所述自定义文本格式（不声称兼容标准SKILL.md）：空行前是元数据、空行后是正文；必填名称/适用条件/启用，允许资料、工具；字段不重复、不接受未知字段；文件最多8000字，正文最多2000字，名称最多32字、触发条件最多120字、资料最多32字；工具只允许knowledge_search。名称班内唯一。创建/更新/删除仅教师。A班数学与语文两份样板按seed_key幂等预置，不覆盖教师修改。技能含“解题引导”时服务端系统约束不得给最终答案/得数/完整过程。

### D4：智能体配置
本班唯一名称最长64字；角色提示词最长2000字，空值使用通用默认角色。教师可创建/修改/启停并整体更新技能、材料绑定；每次提问重读绑定与启停状态，因此变更对已存在会话下一轮生效。材料/技能绑定必须属于同班；学生不能写配置。

### D5：确定性路由与检索
候选技能只取当前智能体已绑定且启用的技能，按逗号、顿号、分号、竖线切分适用词，大小写折叠后对提问做子串计分；至多选最高分技能，同分取ID小者，零分不选。检索调用第4课hybrid能力，只按绑定材料ID及会话班级过滤，最多4条；命中技能的资料字段非空时再按材料标题包含该词过滤。空正文先过滤再连续编号。资料/技能文本均是不可信数据：系统消息只放角色、技能规程及边界，材料内容放user消息。无命中仍生成，citations为空且输出剥除[n]编号；有命中要求引用编号对应元数据。

### D6：消息窗口与流式事务
用户问题2—500字，先持久化；会话首轮标题取问题前24字，随后更新updated_at。每轮上下文使用最近6条非空user/assistant消息、每条最多500字。助手正文、citations_json和skill_name一起落库。SSE先发送meta(skill与citations)，再发只含新增片段的多个delta，最后持久化后发done(message_id)。开始响应后故障发送通用error。若生成器中途失败但已有正文片段，保存已生成正文后结束；无片段失败则在首事件前返回503或事件error，按实际流阶段处理。每帧flush，设置禁代理缓冲响应头；Nginx关闭缓冲并延长读取超时。

### D7：模型与本地验证
抽象流式生成器，生产实现沿用项目课程网关配置但本轮不调用；验收使用本地stub模拟分段、失败和无证据回答。stub结果只算本地模拟，不算真实课程网关验收。

### D8：API文档与前端
处理器注解作为OpenAPI来源；提供/swagger界面。前端用fetch POST并自行按SSE空行/event/data规则解帧，逐段追加、展示meta引用并链接本班材料。现有登录Cookie和CSRF Origin检查沿用。

### D9：三个内置应用与独立提问模板
每个班级幂等建立讲义问答、解题引导、复习整理三个内置智能体，使用数据库映射表保存稳定内置键，不靠可编辑名称判断是否已预置。教师仍能配置角色、启停并绑定本班材料与技能。首页三个应用卡片分别进入对应智能体；前端另提供学生可选提问模板，模板作为用户消息末尾的结构化指引，不替代或修改教师角色提示词。

## Risks and limits

- 教师页面、学生页面与同伴交叉验证需真实浏览器/第二账号证据；本机模拟不能替代同伴验收。
- 课程模型请求禁止；本课生成路径以stub通过验收，生产外部流式适配仍须确认接口行为后单独验证。
- 课程原始canonical spec尚未取得；依据是公开实现教程。
- 本次工作不改变第4课真实材料问答曾超过单条授权范围、当前仍不通过的结论。

## Acceptance approach

先严格校验OpenSpec，再增量迁移与服务端/前端实现；逐层执行Go测试、构建、前端构建、迁移重入与已有数据保持检查、API角色/本人/班级/绑定边界、SSE帧顺序与拼接、stub失败恢复、浏览器操作。每项记录本机真实服务、模拟、外部服务、同伴验证类别。不得调用模型。
